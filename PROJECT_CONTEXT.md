# SkillProof: Master Blueprint & Backend Architecture
*Prepared for: Agentic Development (Claude/Gemini)*

## 1. System Overview
Resume Verifier is a deterministic, rules-based system that extracts skills from a resume, evaluates claimed proficiency levels against a structured question bank, and produces a transparent, auditable verdict for each skill. The system never uses AI to generate scores or verdicts — every decision is a rule firing against structured data.

### 1.1 Core Architecture Design (Stateless Backend)
To optimise for the hackathon, **the Backend is entirely stateless**. 
- The backend serves the SKG, Question Bank, evaluates answers, and returns verdicts.
- The **Frontend React application** is responsible for storing session history, progression state, and past evaluations in `localStorage`. 

### 1.2 Four Stages
1. **Stage 1 — Ingestion:** Parse resume PDF or text, extract skills via taxonomy lookup, detect claimed proficiency levels, build the skill profile.
2. **Stage 2 — SKG Traversal:** Walk the Skill Knowledge Graph to check prerequisites, assign tiers, build the evaluation order queue.
3. **Stage 3 — Evaluation Engine:** Serve question sets, compute composite scores, fire verdict rules.
4. **Stage 4 — Gap Report:** Render Claim vs Reality table, skill radar, audit trail, and ranked roadmap sourced from SKG nodes.

## 2. Data Models (JSON Files)

**SKGNode Object (`skill_graph.json`)**
- `skill_id`: string
- `canonical_name`: string
- `aliases`: string[]
- `tier`: 1 | 2
- `domain`: string (ML | Web | DB | DevOps)
- `prerequisites`: string[]
- `concept_tags`: string[]
- `edge_case_tags`: string[]

**Question Object (`questions.json`)**
- `question_id`: string
- `skill_id`: string
- `question_type`: THEORY | PRACTICAL | EDGE_CASE
- `options`: { id: string, text: string, misconception_tag?: string }[]
- `correct_option_id`: string
- `explanation`: string

## 3. Stage 1 — Resume Ingestion & Skill Extraction
- User pastes raw text. (The UI contains a default minimal resume string for quick testing).
- Taxonomy lookup maps text to canonical IDs.
- Level signals ('expert', 'basic') map to BEGINNER, INTERMEDIATE, EXPERT. 
- Default to INTERMEDIATE if no level signal is found.

## 4. Stage 3 — Deterministic Evaluation Engine
- **Composite Score (Tier 1):** `(theory × 0.3) + (practical × 0.4) + (edge_case × 0.3)`
- **Misconception Tag Collection:** Every wrong answer maps to a specific `misconception_tag` to personalize the roadmap.

### Verdict Rules (Sequential Execution)
- R01: Tier 2 & composite >= 0.60 → BASIC_VERIFIED
- R02: Tier 2 & composite < 0.60 → BASIC_UNVERIFIED
- R03: Tier 1 & composite >= 0.70 → VERIFIED
- R04: Tier 1 & between 0.50 and 0.69 → PARTIAL
- R05: Tier 1 & claimed EXPERT & composite < 0.60 → OVERCLAIM
- R06: Tier 1 & claimed INTERMEDIATE & composite < 0.45 → OVERCLAIM

## 5. Stage 4 — Gap Report & Roadmap
The **Claim vs Reality Table**, the **Radar Chart**, and the detailed **Audit Trail** are rendered.
The **Roadmap** is generated by checking flagged skills, pulling the `concept_nodes` and `edge_case_nodes` from the SKG, and appending the specific `misconception_tag` identified from the user's wrong answers.

## 6. API Contracts (FastAPI - Stateless)

- `POST /api/resume/extract`: Takes raw resume text. Returns extracted `SkillProfile[]`.
- `GET /api/skg/queue`: Frontend passes the extracted profile + prior evaluation history. Backend returns the sorted evaluation queue (handling prerequisite gating).
- `GET /api/evaluation/:skill_id/questions`: Returns questions for the skill (stripped of correct answers).
- `POST /api/evaluation/score`: Frontend sends `{ skill_id, claimed_level, answers: [ { question_id, selected_option_id } ] }`. Backend computes score, fires rules, and returns the full graded `EvaluationSession` object. Frontend saves this to `localStorage`.
- `POST /api/report/roadmap`: Frontend sends the array of completed `EvaluationSession` objects. Backend returns the structured Roadmap data based on the SKG mapping.
